# 配方研发系统 · 数据结构草案 v0.3

> 目标：数值为骨、发现为皮。风味数值层决定品质，成长/市场数值层（开罗式）提供长线驱动，
> 隐藏配方提供发现高潮。数据全部表驱动（JSON），后期扩内容零代码成本，可直接转为 Godot Resource。
>
> v0.2 变更：参考开罗框架与沙威玛传奇互补分析，新增 §6 三层数值驱动结构。
> v0.3 变更（多角色评审）：上架门槛 85→80 并统一评级表；新增每晚保底灵感；黑暗菜单上限 3 格。

## 1. 核心概念

一杯奶茶 = **茶底 × 奶基 × 小料(0~2) × 糖度**

```
组合空间：3 茶底 × 4 奶基 × C(6, 0..2)=22 种小料组合 × 5 档糖度 ≈ 1320 种
隐藏配方：v0.1 共 10 个（约占组合空间 0.8%，靠反馈线索引导发现）
```

## 2. 风味维度（5 维向量）

每个原料贡献一个风味向量，一杯茶的风味 = 所有原料向量之和 + 糖度修正。

| 维度 | key | 含义 | 理想区间（平衡带） |
|---|---|---|---|
| 香气 | `aroma` | 茶香/椰香/焦糖香 | 2 ~ 8 |
| 甜感 | `sweet` | 甜度总和 | 3 ~ 7 |
| 浓郁 | `rich` | 奶感/厚重度 | 3 ~ 7 |
| 清爽 | `fresh` | 回口清爽度 | 1 ~ 5 |
| 嚼感 | `chew` | 小料口感层次 | 2 ~ 6 |

- 落在平衡带内 → 加分；偏离 → 按偏离量扣分。
- **偏离最大的维度决定反馈文案**（见 §5），这是玩家的研发线索。

## 3. 原料表（`data/ingredients.json`）

原料字段：

```jsonc
{
  "id": "brown_sugar",        // 英文 id，代码内引用
  "name": "黑糖冻",            // 显示名
  "flavor": { "aroma": 2, "sweet": 3, "rich": 2, "fresh": 0, "chew": 2 },
  "tags": ["caramel", "heavy"], // 风味标签，驱动相性规则
  "cost": 3,                   // 单杯成本（经营端用）
  "unlock_day": 5              // 第几天可购入（研发节奏门控）
}
```

### 3.1 相性规则（synergy / clash）

基于**标签对**而非原料对，新增原料自动继承规则：

```jsonc
{
  "tags": ["caramel", "robust"],
  "type": "synergy",                       // synergy 相成 | clash 相克
  "bonus": { "aroma": 1, "rich": 1 },      // 相成：附加风味
  "score": 8,                              // 直接加/扣分
  "note": "黑糖焦香与红茶醇厚相得益彰"        // 试喝时可透出的线索文案
}
```

设计原则：
- 相成规则是**隐藏配方的路标**（黑糖×红茶相成 → 引导玩家发现"黑糖珠撞奶"）；
- 相克规则制造记忆点（茉莉清香被厚重小料压死 → "香气全被盖住了"）。

## 4. 隐藏配方表（`data/recipes.json`）

```jsonc
{
  "id": "brown_sugar_boba",
  "name": "黑糖珠撞奶",
  "base": "black_tea",
  "milk": "fresh_milk",
  "toppings": ["boba", "brown_sugar"],   // 集合匹配，不看顺序
  "sugar": [70, 100],                    // 糖度容差区间（避免 5 档全试的挫败）
  "tier": "爆款",                         // 普通 | 招牌 | 爆款 → 决定客流加成
  "price": 18,
  "hype_days": 6,                        // 热度生命周期（天），衰减后需要新配方
  "desc": "虎纹挂壁，甜到心颤"
}
```

### 4.1 发现判定（优先级从高到低）

```
1. 精确命中：base + milk + toppings 集合全等 且 糖度在容差区间
   → ★ 新配方诞生！命名动画 → 进图鉴 → 可上菜单
2. 近似命中（差一个槽位，或只有糖度不对）
   → 透出"接近提示"（见 §5），不揭示答案
3. 未命中 → 按风味评分给等级 + 维度反馈
```

### 4.2 评分公式（未命中时）

```
score = 60（基准）
      + 6 × 落在平衡带内的维度数
      - 5 × 各维度偏离平衡带的总量（每点）
      + Σ 相性规则 score（相成为正，相克为负）
clamp 到 [0, 100]
```

| 分数 | 等级 | 经营端效果 |
|---|---|---|
| ≥ 80 | 优秀 | 可命名上架，进入市场检验（§6.4） |
| 60~79 | 不错 | 不够上架；75~79 额外触发"就差一口气"引导（§5） |
| 40~59 | 平庸 | 无人问津 |
| < 40 | 翻车 | 进"黑暗菜单"，猎奇顾客彩蛋（§6.7） |

## 5. 反馈生成（研发线索的唯一出口）

反馈永远**模糊但有方向**，绝不报数值：

| 触发 | 文案示例 |
|---|---|
| sweet 超上限 | "齁得慌，喝两口就腻了……" |
| sweet 低于下限 | "寡淡，像在喝刷锅水。" |
| rich 超上限 | "太厚重了，糊嗓子。" |
| aroma 低于下限 | "没什么香气，平平无奇。" |
| chew 低于下限 | "口感单薄，一滑到底。" |
| fresh 超上限 | "太寡了，压不住茶涩。" |
| 相克触发 | 透出规则 note（"茉莉的清香全被盖住了……"） |
| 相成触发 | 透出规则 note（"焦香和茶香缠在一起，有点东西！"） |
| 近似命中（差 1 槽位） | "隐约有个熟悉的影子……换一种【小料/奶/茶底】试试？" |
| 近似命中（只差糖度） | "配料没问题，但甜度好像不太对。" |
| 品质分 75~79 | "就差一口气……换个小料或糖度微调下？" |

## 6. 数值驱动组合层（v0.2 · 开罗式优化）

三层结构：

```
第1层 风味数值层（§2~§5）：向量 + 平衡带 + 相性 → 单杯品质分
第2层 成长数值层：原料熟练度 + 相性图鉴 → 重复行为也有产出
第3层 市场数值层：灵感点 + 延时市场检验 → 焊死经营↔研发双循环
```

### 6.1 原料熟练度（学《游戏发展国》类型/内容等级）

每个原料带成长状态（存档字段，不在静态表中）：

```jsonc
{ "ingredient_id": "boba", "level": 3, "xp": 16 }
```

- 试做每用到一次 +1 xp，每 8 xp 升 1 级（Lv1 起步，上限 Lv5）；
- 当前每级效果：Lv1~2 不改变配方；Lv3~5 该原料的主风味维度 +1。主维度 = 该原料风味向量中的最大项；
- 配方图鉴的成长页常驻显示 14 种可用原料的 Lv、当级 0~8 XP 进度条与 Lv3 效果；
  主维度 = 该原料风味向量中的最大项；
- **翻车的试做同样涨 xp**——失败不是纯损失，消除无效操作感。

### 6.2 灵感点（学"研究数据"，双循环的血液）

| 来源（白天经营） | 灵感点 |
|---|---|
| 完美出杯（无失误交付） | +1 |
| 顾客好评 / 小费 | +2 |
| 日结算达成当日目标 | +5 |

- 晚上研发：每次试做消耗 2 灵感点 + 原料成本；
- **每晚保底 8 点灵感**（表现挂钩部分是增量），确保低手速玩家研发不死锁；
- 手速玩得越好 → 灵感越多 → 研发越多 → 爆款拉客流 → 白天更热闹，闭环。

### 6.3 相性图鉴（学"杰作组合表"）

茶底 × 奶基 = 3×4 相性矩阵，评级四档：**绝配 / 相合 / 普通 / 相冲**（由 §3.1 相性规则
汇总计算得出，静态可推导，无需新表）。

- 初始全部显示"？"，**试做过一次才点亮**；
- 点亮全表后每晚保底灵感永久 +2；点亮最后一格的试作会当晚即时返还 2 点，不让完成时刻等到次日才有反馈；
- 相性分 = 同时命中的相成分之和 - 相冲绝对值；相冲不低于相成时优先评为“相冲”，其余依次为绝配（相成 ≥6）、相合（相成 >0）、普通；
- 设计意图：收集目标 + 给玩家社区留"整理攻略表"的传播空间（开罗长寿秘诀）。

### 6.4 市场检验期（学开罗"检验三板斧"：随机性 / 数值复杂化 / 延时揭晓）

新配方上架后**不立刻定级**，走 3 天检验流程：

```
上架 → 每晚结算揭晓当日顾客评分（品质分 ± 随机波动 ±8，受当日天气/事件修正）
     → 第 3 晚汇总定级：爆款 / 招牌 / 普通 / 滞销
     → 定级决定 price 系数与 hype_days
```

- 检验期内每晚多一个"揭晓时刻"，强化"再开一天店"的钩子；
- 滞销品可下架回炉（返还部分灵感点），挫败有出口。
- 每晚用独立卡片显示当日分、当前均分、上涨/回落趋势和 1/3~3/3 进度；第三晚直接显示定级、菜单价与上架/返还结果；
- 品质分 ±8 的体感波动保留，但种子由饮品名/品质/当日/阶段确定；退出重进不改变结果；
- 收工时将整份结算持久化。同日重复结算直接返回原结果，重进研发室会恢复结算面板，不再允许追加试作。

### 6.5 双轨配方

| 轨道 | 触发 | 定级方式 |
|---|---|---|
| 自创配方 | 任意组合品质分 ≥80，玩家命名上架 | 走 §6.4 市场检验 |
| 传说配方（§4 隐藏表） | 精确命中 | 跳过检验，直接按 `tier` 定级 + 进图鉴 |

数值驱动管日常产出，发现时刻管情绪高潮，两轨互不挤压。

定级完成后配方保存完整茶底、奶基、小料、糖度、菜单价与热度，进入夜间 3 槽“明日主推”管理。主推配方白天会生成带名称的真实订单：热卖期每 4 个普通到店机会出现一单、每款使到店速度 +4%、菜单价上再加 2 金币首发溢价；热度归零后保留菜单价并降到每 6 个机会出现一单。特殊顾客规则优先，主推不会覆盖评审、网红或团客订单。

### 6.6 研发任务 checklist（学开罗"一本道"目标设计）

- 已落地一张常驻研究单，只发布玩家当前确实能完成的内容：
  - 奇数日优先从已解锁但未点亮的茶底×奶基中指定一组；
  - 偶数日优先选取一种 Lv3 以下原料，要求连续累计 2 次试作；
  - 12 格相性和所有原料 Lv3 都完成后，切换为单杯品质 ≥75 的稳定性挑战。
- 研究单未完成时跨夜保留；完成后即时返还 2 灵感，但当天不再发布第二张，无法通过重进场景刷取；
- 长期目标弱提醒：图鉴收集率、相性矩阵点亮率；
- 短期达成自动推进长期进度条（目标梯度效应）。

### 6.7 黑暗料理与话题度（社交引爆层，但先过"游戏性优先"铁律）

设计前提：黑暗料理必须在玩法循环中有真实功能，造梗/传播只是附加收益。

**双经济结构**：正经配方赚金钱，黑暗料理赚**话题度（buzz）**，两条线在"客流"汇合：

```
话题度来源：黑暗菜单真实成交（干净且批次未过熟 +2，否则 +1）/ 黑暗传说配方发现（+6~10）/ 猎奇事件
话题度结算：每日清零，转化为次日客流加成 + 额外灵感点（buzz 直接计入次日灵感预算）
策略分支：正经研发赚钱 vs 猎奇研发赚流量，玩家权衡而非纯搞笑
```

**三个玩法功能**：

1. 翻车出口（强化 §4.2）：品质分 <40 生成带完整茶底、奶基、小料、糖度、品质与猎奇价的黑暗菜单候选——失败是可经营的分支而不是纯惩罚；
   **黑暗菜单上限 3 格**，满时即时打开槽位面板，预览候选与三款在售公式后指定替换。每 5 个普通到店机会轮转一单真实猎奇订单；只有正确成交才产生 buzz，占槽不再被动结算——稀缺才有选择，也不能靠“无脑占满”击穿双经济权衡；
2. 黑暗传说配方（`data/dark_recipes.json`）：公认黑暗组合（香菜奶茶、折耳根特调）做成
   隐藏图鉴，精确命中另弹专属高光演出——梗附着在收集系统上才有持续生命力；
3. 猎奇原料门控：`weird` 标签原料（香菜碎、折耳根）后期解锁，自带强相克规则，
   保证黑暗组合必然低分落入黑暗轨道，不污染正常风味体系。

**社交钩子（游戏外功能，后置）**：黑暗传说发现时生成分享卡（配方名 + 毒舌试喝评语 +
杯子渲染图）；黑暗图鉴收集率做成排行榜。截图即传播素材。

## 7. 与经营循环的接口（已实现）

- `cost` / `price` → 主推订单实际成交价；不再按菜单条目被动发放日结算收入；
- `tier` + `hype_days` → 上新主推拉客流、首发溢价与热度衰减；每营业日只结算一次，防止重复衰减；
- `unlock_day` → 原料随进度解锁，控制研发内容投放节奏；
- 每日研发次数由灵感点 + 原料库存双重限制（§6.2）。

## 8. 移植到 Godot 的映射

| 原型 | Godot |
|---|---|
| ingredients.json / recipes.json | 直接 `JSON.parse_string()` 加载，或转 `Resource` (.tres) |
| recipe_lab.py 的评分/判定逻辑 | 单例 `RecipeLab.gd`（纯逻辑，无场景依赖，便于单测） |
| 熟练度/图鉴/检验期状态 | `SaveData.gd`（用户存档，与静态数据表分离） |
| CLI 反馈文案 | 试喝气泡 UI + 顾客表情 |
| 市场检验揭晓 | 晚间结算面板的逐条弹出动画（开罗式媒体评分演出） |

---

**验证方式**：先玩 `prototype/recipe_lab.py`（终端文字版）。判断标准：
1. 不看答案的情况下，10~20 次试做内能否靠反馈摸出 2~3 个配方？
2. 发现配方的瞬间是否有"啊哈"感？
3. 翻车反馈是否好笑而非沮丧？

任何一条不成立 → 调数据表（反馈粒度 / 容差区间 / 相性提示强度），不改代码。
