# 员工系统 · 数据结构与首批实现 v0.2

> 铁律：游戏性优先。员工不是干巴巴的效率数值，而是"功能单元 + 事件发生器 + 行走的梗"。
> 设计同构于配方系统："数值打底（养成留存），特质造戏（内容与传播）"。
> 数据表驱动：`data/traits.json`，加特质零代码成本。

## 1. 双层结构

```
第1层 功能数值：手速 / 细心 / 亲和（3 项，可成长）→ 决定自动化效率
第2层 性格特质：每人 1~2 个，全部双刃剑        → 决定事件、策略与梗
```

## 2. 功能数值（第 1 层）

| 属性 | key | 范围 | 影响 |
|---|---|---|---|
| 手速 | `speed` | 1~10 | 自动做单速度（每点 -6% 单杯耗时） |
| 细心 | `care` | 1~10 | 出错率（做错配料/糖度，基础 12%，每点 -1%） |
| 亲和 | `charm` | 1~10 | 顾客耐心条衰减速度、小费概率 |

- **成长**：出杯累计经验，每级随机 +1 到某属性（权重可配），上限 Lv8；
- 工资 = 底薪 × (1 + 属性总和 × 0.06) × 特质工资系数——强员工贵，特质抵扣，构成招聘权衡。

## 3. 性格特质（第 2 层）

### 3.1 设计铁律

1. **没有纯 buff**：每个特质必有代价，且代价必须能"演出来"（可见的行为/事件），不是暗扣数值；
2. **至少一半特质要与经营外系统咬合**（研发/黑暗料理/话题度），员工不是经营端孤岛；
3. **特质 = 事件发生器**：白天的戏剧性事件全部由特质驱动，玩家的"管人"压力来源于此。

### 3.2 特质字段（`data/traits.json`）

```jsonc
{
  "id": "pure_fool",
  "name": "清澈又愚蠢",
  "emoji": "🌟",
  "rarity": "rare",              // common / rare —— 决定招聘池出现率
  "wage_mult": 0.5,              // 工资系数（<1 便宜，>1 贵）
  "stat_mods": { "speed": 0, "care": -2, "charm": 1 },   // 常驻属性修正
  "hooks": [                     // 效果钩子：type 由代码实现，参数全在表里
    { "type": "no_stamina_drain", "note": "热情满格，体力不衰减" },
    { "type": "wrong_ingredient", "chance": 0.10,
      "clue_chance": 0.15,
      "note": "随机做错配料；错杯若恰好命中隐藏组合，有 15% 概率产生研发线索（不直接解锁）" }
  ],
  "event_lines": [               // 事件弹幕文案（演出素材）
    "（把黑糖舀进了茉莉纯茶）诶？这个不是糖吗？",
    "老板！我今天一杯都没做错！……大概。"
  ]
}
```

`hooks.type` 是有限枚举（代码实现一次，所有特质复用），v0.1 枚举见 §3.3 表格"钩子"列。

### 3.4 招聘 = 开盲盒（延时揭晓再次适用）

- 面试只显示：3 项数值 + 工资 + 一句自我介绍（**介绍文案暗埋特质线索**，如"我这个人吧，就是特别实诚"→清澈愚蠢）；
- 特质入职后不显示，**靠事件首次触发时揭晓**（弹出"特质觉醒：🌟清澈又愚蠢"）；
- 翻车员工本身是乐子 + 截图素材；开除有一次性遣散费，留人换人是真实决策。

## 4. 与现有系统的咬合点

| 系统 | 咬合方式 |
|---|---|
| 配方研发 | 清澈愚蠢的错杯产出**研发线索**（不直接解锁，保护"发现管高潮"支柱）；夜猫子降低研发灵感消耗 |
| 黑暗料理/话题度 | 错杯低分自动进黑暗菜单；显眼包直接产话题度 |
| 灵感点经济 | 员工自动出杯同样产灵感（效率低于玩家手操，保证手操始终有价值） |
| 白天操作循环 | 摸鱼要拍醒、干饭要抓包、社恐要替他接待——"手速"压力升级为"手速+管人" |

## 5. 节奏投放

| 阶段 | 内容 |
|---|---|
| 第 1 家店 | 无员工（验证单人手操循环） |
| 第 8~10 天 | 解锁第 1 个雇员位（common 池） |
| 第 2 家店 | 雇员位 ×3，解锁 rare 池、员工升级 |
| 后期 | 员工排班（早/晚班对应夜猫子等时段特质）、特质羁绊（社牛×社恐同班触发专属事件） |

## 6. 移植到 Godot 的映射

| 原型 | Godot |
|---|---|
| traits.json | `JSON.parse_string()` 加载；hooks 由 `StaffHooks.gd` 枚举分发 |
| 员工实体 | `Staff.gd`（数值+特质引用+状态机：工作/发呆/自拍/僵住/偷吃） |
| 事件弹幕 | 头顶气泡 + 事件日志（截图传播位） |
| 招聘盲盒 | 面试 UI（简历卡片，特质线索藏在自我介绍里） |

## 7. 首员工位实现状态（2026-08）

第 8 天起夜间研发室开放一个岗位，首批 common 池提供三名固定候选人。面试只展示手速/细心/亲和、日薪和带线索的自我介绍；特质在白天第一次真实触发后揭晓。

| 候选人 | 隐藏特质 | 已实现好处 | 已实现代价 / 互动 |
|---|---|---|---|
| 小满 | 摸鱼大师 | 值班时后排耐心消耗 -30%，日薪仅 6 | 每 20~28 秒可能摸鱼；照看效果暂停，点击 3D 店员或按 F 拍醒 |
| 桃子 | 社牛 | 全场耐心 +20% | 到店间隔 -12%，客流、收入机会和操作压力同时增加；日薪 12 |
| 阿澄 | 强迫症 | 正确杯 +2 金币，每天拦下 1 杯错单且不损耐心/连击 | 每杯多摇 1 下复核；日薪 14 |

招聘费 45 金币；解除合同需 20 金币并二次确认。工资在日结算中明确扣除，员工状态与觉醒特质进入存档、标题页摘要和 14 天统计。

三名候选人现在各自绑定独立 Blender MCP 模型，而不是共用一名换色店员：小满使用软塌薄荷帽、半垂眼、平嘴和随身杯；桃子使用高侧马尾、薄荷发圈与耳麦；阿澄使用深色眼镜、检查板、笔和计时徽章。源文件位于 `assets_src/blend/staff_{xiaoman,taozi,acheng}.blend`，运行时位于 `game/assets/glb/` 同名文件，分别为 3,024 / 3,290 / 3,088 三角面和 9 个合批网格，均符合 GDD 角色级 2,000~3,500 面预算。`staff_barista.glb` 保留为未知员工 ID 的兼容回退。

后续池仍包括社恐、干饭人、夜猫子、显眼包与清澈又愚蠢；它们需要库存、研发线索或时段排班系统后再落地，避免只实现文案不实现真实代价。
