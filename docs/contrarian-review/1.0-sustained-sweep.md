### S2: Campaign stats lost on load — relief-day eligibility and summary counters silently reset
- Evidence: `game_state.gd:_normalize_campaign_stats()` rebuilt `campaign_stats` from `_new_campaign_stats()` and restored 19 ledger keys + `recorded_days`, but never restored `day_stars`, `relief_days`, `critic_served`, `matched_served`. `save_integrity_check.gd` had zero campaign-stats round-trip coverage.
- Impact: `day_shop.gd` computes `goal_relief` from `GameState.yesterday_stars(day) >= 0`; after any mid-campaign app restart (the resume flow `phase` exists for), `yesterday_stars` returns −1, so the D5 relief day (goal ×0.85, floor 60) silently never triggers for the first day after reload. `campaign_summary.gd` under-reports relief days and drops the critic/matched lines. Compounding trap: JSON serializes int dict keys to strings, so a naive restore would still fail `day_stars.get(int)` lookups.
- Fix direction (applied): restore the four fields in `_normalize_campaign_stats`, coercing `day_stars` keys back to int (clamped 1–14, values 0–3), bounding `relief_days ≤ days_completed` and `critic/matched ≤ served` for forgery parity. Failing test written first in `save_integrity_check.gd` (JSON round-trip through `_save_snapshot` → parse → `_apply_save_data`); confirmed failing, then green after the fix. Full 25/25 gates green.
